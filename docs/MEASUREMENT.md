# 결과 판정

실행기는 운영 공간의 `control/verified-events.json`을 읽습니다. 이는 운영자가 원천을 확인해 입력하는 기록이지, 자동으로 진위를 인증하는 시스템은 아닙니다. 에이전트의 최종 응답이나 스스로 붙인 성공 판정은 이 파일을 변경하지 않습니다.

각 event는 `id`, `kind`, `account_id`, `occurred_at`, `evidence_ref`, `confirmed_by`를 갖습니다. `evidence_ref`는 운영 공간에서만 의미 있는 근거 참조이고, `confirmed_by`는 `operator`입니다. 이 입력은 명시된 시작 시각부터 기한까지, 현재까지 발생한 사건만 셉니다. 기준값에 들어간 회사는 신규 참여·신규 유료 파일럿에서 제외합니다.

| kind | 의미 | 중복 제거 |
| --- | --- | --- |
| `workflow_conversation` | 최근 업무를 구체적으로 확인한 실제 대화 | 회사 |
| `workflow_participation` | 담당자가 실제 업무와 시간/자료를 제공 | 신규 회사 |
| `playback_delivered` | 맞춤 비교 결과를 실제 반환 | 회사 |
| `evidence_backed_revision` | 실반응 → 방법 변경 → 후속 실행을 확인 | event ID |
| `paid_pilot` | 파일럿의 실제 결제 확인 | 신규 회사 |

동일 event ID가 반복되면 입력 오류로 중지합니다. 원천이 없는 레코드, 미래 날짜, 시작/종료 범위 밖 사건은 성과를 올리지 않습니다. 연락 요청, 연결 수락, 조회수, 예약, 호평은 위 성과를 대신하지 않습니다. 실제 매출·금액과 비용은 운영 공간에서 관리하고 제출 템플릿에는 넣지 않습니다.

기한 종료·호출 한도 소진·오류·운영자 중지는 `goal_reached`와 구분합니다. 7일 안에 관찰이 끝나지 않은 상대는 실패로 단정하지 않습니다. 작은 표본의 변경 전후 차이는 학습 근거이며 통계적 우월성 주장이 아닙니다.
