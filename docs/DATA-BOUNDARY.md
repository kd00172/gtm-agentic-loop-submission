# 제출 정보와 운영 정보

제출 폴더에는 방법론, 범용 프롬프트, 실행 코드, 스키마, 완전한 합성 예시만 둡니다. 실제 회사나 고객을 이름만 바꾸어 복사하지 않습니다.

운영 폴더는 제출 저장소 **밖**에 만듭니다. 실제 제품 설명, 고객 선정 근거, 연락처, 대화, 정확한 발송 문안, 승인, 원천 URL, 계정/PR/인프라 식별자, 결과와 모델 로그는 그곳에만 둡니다. 실행기는 저장소 안의 운영 경로와 심볼릭 링크를 거절합니다.

운영 결과는 자동으로 제출 폴더에 복사되거나 Git에 추가되지 않습니다. `report`는 고정된 지표 이름과 정수 집계, 실행 상태만 반환합니다. 입력 문장, 고객별 ID, 근거 참조, 금액, 파일 경로는 내보내지 않습니다. 실제 집계를 공유할지 여부는 별도 결정입니다.

`submission-files.txt`가 제출 파일의 정확한 허용 목록입니다. `.gitignore`도 이 파일만 추가 가능하도록 제한합니다. 커밋·push hook은 허용 목록과 흔한 식별정보/자격정보 형태를 검사합니다. 경로를 허용했다고 그 내용이 승인되는 것은 아닙니다. 의미상 민감한 정보까지 완전히 탐지하는 검사는 아니므로 실제 자료를 이 폴더에 넣지 않는 방식이 기본입니다.

Codex CLI는 운영 입력을 모델에 전달합니다. 이 설계는 GitHub 제출 경계이며 모델 제공자까지 포함한 데이터 격리 장치는 아닙니다. 실제 운영 입력의 사용 범위는 운영자가 정합니다.
